# План: свой бот и /notify в tg-proxy-check

> Исполняется скиллом execute: свежий исполнитель на задачу; задача видит
> только собственный текст. Шаги — чекбоксы `- [ ]`.

**Спека:** docs/sberpowers/specs/2026-10-07-own-bot.md (REQ-pxc-12, 13; MODIFIED 05, 07, 08; REMOVED NOTIFY)
**Цель:** ⚠️/✅ и `/notify` идут от собственного бота мониторинга, без зависимости от Worker'а tg-digest.
**Архитектура:** `worker.js` получает обработчик `fetch` (`POST /notify`) и функцию отправки владельцу через Telegram
Bot API; тест подменяет глобальный `fetch`. `deploy.sh` ставит секреты бота вместо service binding и включает
поддомен workers.dev. Потребители `/notify` (стенд, `tg-me`) переключаются оператором.

## Глобальные ограничения
- Бесплатный Workers: ≤ 10 мс CPU, ≤ 50 подзапросов на вызов.
- Окружение Worker'а: `STATE` (R2), `ADMIN_KEY` (secret), `BOT_TOKEN` (secret), `OWNER_ID` (plain), `PROXIES` (plain).
  Binding'а `NOTIFY` больше нет.
- Контракт `/notify` — как был у tg-digest: `POST /notify?key=<ADMIN_KEY>`, тело — текст (HTML Telegram можно).
- Секреты не попадают в аргументы внешних процессов (curl — `-H @файл`, `-K файл`).
- Публичный репозиторий: ни IP (кроме `127.0.0.1`), ни ключей, ни имени бота (в примерах — `@your_bot`).
- Node 18+, без npm-зависимостей. Вторая строка заголовка изменённого файла — `YYYY-MM-DD HH:MM · vX.Y · Nick Churkin`
  (MSK, `TZ=Europe/Moscow date '+%F %H:%M'`), версия +0.1.
- Коммиты: автор из `git config`, в конце сообщения `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Ошибки не глотать: неуспех Telegram — исключение (для ⚠️/✅ состояние не пишется, REQ-pxc-10).
